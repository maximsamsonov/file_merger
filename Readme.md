# Система загрузки и обработки телефонных данных (CSV)

## Описание задачи

Разработана высокопроизводительная система на C для:

- Загрузки основного набора данных из CSV-файлов (до 300 млн записей) за < 1 минуты.
- Применения инкрементов (добавление/удаление/обновление записей по номеру) со скоростью до 10 записей/с.
- Быстрого поиска записи по телефонному номеру.
- Сохранения объединённых данных в CSV-файл, отсортированный по номеру.
- Минимального использования памяти (структура записи – 32 байта, строки – в общем пуле).

**Целевое железо:** CPU 2.4 ГГц, 24 потока, 128 ГБ ОЗУ.

## Архитектура проекта

Проект разбит на логические модули для удобства чтения и поддержки:

| Файл               | Назначение |
|-------------------|------------|
| `types.h`         | Общие структуры данных (`phone_t`, `Record`, `Change`, `ChangeHash`) |
| `utils.{h,c}`     | Парсинг/форматирование номеров, хеш-функция |
| `hash.{h,c}`      | Хеш-таблица для хранения изменений (инкрементов) |
| `load.{h,c}`      | Параллельная загрузка основных CSV-файлов (mmap + потоки) |
| `sort.{h,c}`      | Параллельная сортировка слиянием (merge sort) массива `Record` |
| `inc.{h,c}`       | Загрузка инкрементов из CSV-файлов |
| `search.{h,c}`    | Бинарный поиск по отсортированному массиву |
| `save.{h,c}`      | Слияние основного массива и изменений, запись в CSV |
| `test.c`          | Тестовая программа с генерацией файлов и проверкой |

## Ключевые технические решения

- **Телефонный номер** – хранится как 128-битное целое (`unsigned __int128`), что позволяет компактно представить до 19 hex-цифр.
- **Строки (комментарии, даты)** – вынесены в единый пул байт, записи содержат только смещение и длину. Это минимизирует фрагментацию и экономит память.
- **Загрузка основных файлов**:
  - Используется `mmap` для быстрого отображения файлов в память.
  - Файлы разбиваются на чанки (по 256 МБ), каждый чанк обрабатывается в отдельном потоке (до 24 потоков).
  - Парсинг строк выполняется параллельно, записи добавляются в общий массив с атомарным счётчиком.
- **Сортировка** – параллельная сортировка слиянием с порогом переключения на `qsort` (для фрагментов ≤ 1024 записей).
- **Инкременты** – загружаются в хеш-таблицу с цепочками для разрешения коллизий. Ключ – номер телефона, значение – операция (A/D/U) и данные.
- **Поиск** – сначала проверяется хеш изменений (O(1)), затем бинарный поиск по основному массиву (O(log N)).
- **Сохранение** – объединяет основной массив и изменения, удаляя помеченные записи и применяя обновления/добавления, результат записывается в CSV.

## Сборка и запуск

### Требования

- Компилятор GCC (поддерживает `__int128` и `-pthread`)
- ОС Linux (используются `mmap`, `pthread`, `getline`)
